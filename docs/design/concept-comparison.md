# UI-01 三种视觉方案对比与推荐

## 1. 共同基线

三种方案都遵循以下不可变约束：

- 面向 Windows Qt Widgets 的单机工业控制工具，不使用通用后台模板、营销卡片或花哨渐变。
- 字体统一使用 **Segoe UI**；控件高度、面板间距、圆角和命中区使用 Qt 逻辑像素，并覆盖 100%/125%/150%/200% DPI。
- 主窗口结构固定为：顶部连接/模式状态栏、左侧导航树、右侧工作区、底部采集状态栏。
- 左侧导航固定包含：**PLC 配置、Tag 编辑、看板、趋势、报警、历史、配方、日志**。
- 编辑模式和运行模式严格分离：编辑模式只改画布和属性，绝不产生 PLC 写请求；运行模式锁定布局，只显示实时数据并允许经过安全校验的按钮操作。
- Good、Stale、Bad、Disconnected 同时用颜色、图标和文字表达；按钮固定有 Normal、Hover、Pressed、Disabled、Waiting 五种状态。
- 看板编辑器使用网格、蓝色选中边框与 8 个手柄、绿色吸附参考线；运行画面使用纯色背景且不显示选中框。

详细 token 和布局规则分别见：

- [`concepts/light.md`](concepts/light.md)
- [`concepts/dark.md`](concepts/dark.md)
- [`concepts/mixed.md`](concepts/mixed.md)

## 2. 方案摘要

| 方案 | 编辑模式 | 运行模式 | 最适合的工作重点 |
|---|---|---|---|
| 工业浅色 | 浅色面板 + 高对比网格 | 浅色纯色画布 | 配置、编辑、调试频率高，监控时间较短 |
| 工业深色 | 深色面板 + 深色网格 | 深色纯色画布 | 长时间值守、低照度环境、运行监控优先 |
| 深浅混合 | 浅色高对比编辑器 | 深色低疲劳运行画面 | 同时重视看板组态精度和长期运行监控 |

## 3. 工业浅色方案

### 优点

1. 网格、蓝色选中框、绿色参考线和白色属性面板之间的层级最容易被新用户理解。
2. 与 Windows 默认桌面和 Qt Widgets 控件习惯接近，表格、表单、Tag 编辑和配置页的迁移成本低。
3. 1366x768 的低分辨率下，文字和边框不容易陷入深色面板；打印截图、故障记录和培训材料更清楚。
4. 编辑/运行虽然需要依赖模式标签区分，但整体视觉连续，用户不容易把主题切换误认为页面重载。

### 缺点

1. 运行画面大面积浅色背景在长时间值守、暗室或夜班环境中更容易造成视觉疲劳。
2. 报警红、Stale 黄与浅色表格底色的可用面积较小，需要严格限制整行染色，否则很快变得刺眼。
3. 当看板组件本身采用白色填充时，必须保留 `#F8FAFC` 画布底色和边框，否则组件边界不明显。

### 风险与控制

- 使用冷灰 `#F2F5F7` 而不是纯白窗口背景；报警只使用左侧色条和浅色底。
- 运行画面仍隐藏网格和选中框，不能因为同一主题而保留编辑残留。
- 状态色与文字/图标并用，避免浅底上的红黄绿对色觉差异用户不友好。

## 4. 工业深色方案

### 优点

1. 深色纯色运行画面适合长时间监控，减少白色屏幕对眼睛的刺激；实时数值、状态点和报警色更容易成为视觉焦点。
2. 编辑和运行从视觉上天然沉浸，适合以看板监控为主的操作台；趋势图的多条曲线在暗底上具有较好的聚焦效果。
3. 连接、写入等待和报警可以通过有限面积的亮色表达，不需要大面积色块。

### 缺点

1. 低对比的灰色边框和禁用文字在高 DPI、小字体和投影环境下容易消失，需要严格执行文字/边框亮度基线。
2. 深色编辑网格需要专门调校，若网格过暗会影响对齐，过亮又会产生噪点。
3. 表单、表格和属性面板需要一套完整的深色 Qt 样式，初期实现和视觉验收成本高于浅色方案。
4. 在明亮车间、截图打印或用户习惯 Windows 浅色界面时，深色全局主题可能增加认知切换。

### 风险与控制

- 背景使用蓝灰 `#111820`，面板至少提升到 `#1B242D`，边框保持 `#3A4854`；关键文字不低于 `#B4C0CA`。
- Waiting 橙色使用深色文字；红黄绿状态仍显示图标和标签。
- 深色模式也要有编辑/运行文字标签和可见工具变化，不能只依赖“整体变暗”。

## 5. 深浅混合方案

### 优点

1. 编辑器使用浅色高对比度：网格、8 个手柄、蓝色选中边框、绿色吸附线、表单和属性分组最容易精确操作。
2. 运行画面使用深色纯色背景：适合长时间监控，亮色质量状态、趋势曲线和报警标记具有更高注意力优先级。
3. 模式视觉差异与产品安全边界一致：浅色代表“可配置但不会写 PLC”，深色代表“布局已锁定、实时运行”。
4. 可以让配置/Tag/看板编辑页沿用 Windows 工具习惯，同时让运行看板适应值守场景；不需要在编辑器和运行画面之间牺牲任一目标。

### 缺点

1. 需要维护两套颜色 token、控件样式和趋势/报警表面，视觉实现与验收成本最高。
2. 用户可能把主题切换理解为异常或页面重载，因此必须固定空间骨架、显示模式标签并在切换时提供明确反馈。
3. 同一组件在编辑预览和运行画面中的边框、文字和状态色需要逐项定义，否则会出现“设计稿一致、实际实现漂移”。
4. 亮度切换可能对极少数对闪烁/高对比敏感的用户造成不适，需要避免动画，并保持切换过渡直接、短暂且可预测。

### 风险与控制

- 两种模式共享相同的导航位置、顶部/底部状态栏高度、字体和逻辑尺寸，只改变主题 token 和可见功能。
- 切换前后明确显示“编辑模式 / 不会写入 PLC”和“运行模式 / 布局已锁定”，同时处理未保存内容和点动释放。
- 运行模式不使用纯黑或全屏闪烁；编辑模式不把质量色误当成选中色，蓝色选中与绿色参考线保持独立。

## 6. 评分对比

评分为 1–5 分，5 分代表更符合本项目目标；“实现成本”分数越高表示成本越低。

| 评价维度 | 工业浅色 | 工业深色 | 深浅混合 | 说明 |
|---|---:|---:|---:|---|
| 编辑器网格/属性可读性 | 5 | 3 | 5 | 编辑操作需要精确看见边界和参考线 |
| 长时间运行舒适度 | 2 | 5 | 5 | 混合方案只把长期监控画面做深色 |
| Windows/Qt 习惯一致性 | 5 | 3 | 4 | 编辑器仍保持浅色，运行画面有明确模式差异 |
| 模式安全边界可见性 | 3 | 3 | 5 | 混合亮度变化与文字/工具变化共同提示模式 |
| 趋势和报警聚焦 | 3 | 5 | 5 | 深色运行画面让曲线和状态更突出 |
| 低分辨率适配 | 5 | 4 | 4 | 混合需避免模式切换造成布局差异 |
| 主题实现成本（成本越低分越高） | 5 | 3 | 2 | 混合需要维护编辑/运行两组 token |
| 总体匹配本项目 | 4 | 4 | **5** | 单 PLC、自由画布、编辑/运行严格分离 |

## 7. 推荐：深浅混合方案

推荐 **深浅混合方案** 作为 UI-02 的首选方向：

1. **直接对应使用场景**：编辑看板是精确配置工作，需要浅色网格、表单和选择反馈；运行看板可能连续值守数小时，更适合深色纯色画布。
2. **直接对应安全模型**：本项目强制编辑模式禁止写入、运行模式锁定布局。浅/深主题变化加上明确的模式文字和工具栏变化，可以降低误操作风险。
3. **兼顾两类页面**：PLC 配置、Tag 编辑、历史筛选和属性面板保留 Windows 工具的熟悉感；趋势、报警和运行看板在运行状态下使用深色，状态色更聚焦。
4. **不会牺牲工业可靠性**：两套主题都使用扁平色块、有限圆角、无渐变和状态的颜色+图标+文字组合，差异只服务于任务，不是装饰。

### 推荐方案的实现前提

- 先冻结共用 token：Segoe UI、逻辑尺寸、导航顺序、顶部/底部状态栏高度、质量状态语义、按钮五态和编辑器网格行为。
- 再分别冻结 `editor.*` 与 `runtime.*` 颜色 token；同一组件禁止在代码中散落 HEX 值，主题切换由集中样式/设计 token 驱动。
- 模式切换必须是原子行为：更新主题与可见工具、锁定/解锁画布、释放点动按钮、处理未保存提示，最后更新模式标签。
- 在 1366x768、1920x1080、2560x1440 及 100%/125%/150%/200% DPI 下做截图审查，重点检查文字裁切、网格可读性、状态色对比和运行模式无选中框。

## 8. UI-02 选择时的快速决策

| 如果优先考虑…… | 选择 |
|---|---|
| 以配置、调试为主，运行时间短 | 工业浅色 |
| 几乎全天候运行监控，环境偏暗 | 工业深色 |
| 既要高精度组态，又要长时间值守 | **深浅混合（推荐）** |
